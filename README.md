# ScorePath Practice

Free, original SAT / ACT / TSIA2 practice: skill-tagged questions with full explanations, mistake-pattern analysis (concept gap, process error, reading trap, pacing/guess), pacing tools, a Teacher Classroom for live in-class sessions with roster and error analytics, and an optional student account for cross-device sync.

V20 focused on clearer navigation, a simplified header, direct exam selection, a redesigned Teacher Classroom, and 6-character alphanumeric class codes.

## What this pass fixed and added

This repository came in as a "GitHub ready" export with a few gaps that would have broken it on a real static host. This pass closed those and layered on the pieces needed to run the site professionally, monetize it, and get it indexed:

**Fixed a real bug that broke most of the site.** `index.html` had two `$("heroTimed").onclick=...` calls targeting an element ID that doesn't exist anywhere in the page. Because that line lived inside a large inline `<script>` block, the resulting `TypeError` aborted the rest of that script — silently skipping the `satStore`/`satState`/`actStore`/`actState` declarations and everything after them. That, in turn, is why the SAT/ACT dashboards, mistake history, goal ring, and focus-lock features threw `is not defined` errors at runtime. Fixed with a small null-safe `safeClick()` helper; verified with Playwright that all pages now load with zero console errors.

**Fixed a second, separately-hidden bug in Teacher Classroom.** `teachers.html` read and wrote a `securityEvents` array (for the Secure Timed Mode activity log) that was never declared anywhere. Every call to `renderAll()` — including the one that runs immediately on page load — threw `securityEvents is not defined` partway through `renderRoster()`, which silently skipped `renderOverview()`, `renderQuestions()`, `renderStudentsTab()`, and `renderSkills()` every single time. In practice this meant the Overview, Questions, Students, and Skills analytics tabs never populated, ever — the single biggest feature this platform has over a plain question-answering site was completely non-functional. Fixed by declaring `securityEvents=[]` alongside the other session state. Verified end-to-end with two real browser tabs (a teacher room + a student joining, answering, and finishing): roster sync, live progress, and all four analytics tabs now populate correctly.

**Made a defensive console wrapper (`spConsole`).** Some embedding/preview contexts run pages inside a sandboxed `<iframe>` with a restricted `console` shim that only implements a subset of the real console API. This page called `console.info(...)` in three places (bank-size diagnostics) and `console.error(...)` in one; in an environment where `console.info` isn't a function, that throws and can abort a script block the same way the `heroTimed` bug did. All four calls now go through `spConsole(method, ...)`, which checks the method exists before calling it and silently no-ops instead of throwing if it doesn't. Verified by simulating a restricted console (only `log`/`warn`/`error`, no `info`) in Playwright — zero errors.

**Added real Open Graph / Twitter Card images and an Apple touch icon.** `index.html`, `sat.html`, `act.html`, `tsia2.html`, and `teachers.html` had no `og:image` at all, so a link shared in Slack, iMessage, or Twitter/X would render as a bare title with no preview image, and "Add to Home Screen" on iOS (outside the PWA manifest flow) had no icon to use. Generated `og-image.png` (1200×630, on-brand) and wired up `og:image`, `og:url`, `og:site_name`, `twitter:image`, and `twitter:card=summary_large_image` on all five pages, plus `<link rel="apple-touch-icon">`.

**Added the five files `index.html` and the account/classroom pages already referenced but that weren't in the export:**

- `sw.js` — a conservative service worker: caches only same-origin pages for offline access, never touches third-party requests (Desmos, Firebase, AdSense, fonts), and always fetches fresh over cache.
- `favicon.svg` / `app-icon.svg` — the site linked to both filenames; both now exist with the same brand mark.

**Wired up real, consent-gated Google AdSense.** The CSS already had `.adSlot` / `.adZone` placements hidden by default and only revealed via an `.ads-enabled` class that nothing ever set — the plumbing existed but nothing was connected. Added:

Verified with Playwright across all 15 non-home pages.

**Replaced the placeholder `contact.html` mailto link with a real contact form that never exposes an email address.** The old page displayed `support@scorepathpractice.com` directly in the HTML (copyable and scrapeable) and did nothing but open the visitor's own mail client. No email address appears anywhere in `contact.html`'s HTML or JS. **Audited the entire 5,000-question bank and fixed a real generator bug that was silently duplicating questions.** *(Historical note added in the Twenty-eighth pass: at the time this section was written, the site's hero copy, about page, and Trust Center described the practice bank as having 5,000 original questions — that copy has since been changed to not state a specific number, see "Known gaps" and the Twenty-eighth pass below; the paragraph below is left as originally written to preserve the audit trail of what was found and fixed at the time.)* At the time of this pass, the site claimed (in its hero copy, about page, and Trust Center) that the practice bank had 5,000 original questions. To verify that claim, every question in `window.ScorePathBank` was extracted with Playwright and checked programmatically: structural completeness (unique ID, valid answer index, four unique choices, a real explanation, choice-by-choice rationale, a strategy tip — the same rule `QUESTION-BANK-QUALITY.md` already documents), full-text duplication (same question + passage + choices + answer as another item), and, for every math item whose format could be parsed, an independent recomputation of the correct answer from the numbers in the question text. The recomputation (1,122 math items checked) found **zero wrong answer keys** — every math item's marked answer really is correct. But the duplication check found a serious problem: the "5,000-question" generator (`v17SATOne`/`v17ACTOne`/`v17TSIOne`, the code that builds most of the bank) had a bug where a question's internal parameters were selected using `i % 12` (or `% 10` for TSIA2) — the exact same number used to pick *which* question template to use for a given slot. Whenever a parameter's own cycle length divided evenly into that same 12 (or 10), the parameter came out **constant** for every single item generated by that template, instead of varying. In practice this meant things like a circle's radius, a sentence's subject noun, or an example passage's name were frozen to one value for the entire life of a template — so the "5,000 questions" were actually well under 1,000 distinct questions, each copy-pasted under a different ID to hit the count target. The worst single offender ("Which inference is most reasonable?" in the TSIA2 bank) was the literal same question repeated 189 times. Fixed the root cause — parameters now derive from a separate counter (`Math.floor(i / cycle length)`) that is never tied to the template-selection index — corrected one knock-on math bug the fix exposed (a circle radius of 2 made two answer choices coincide), and meaningfully expanded several of the smallest hard-coded vocabulary/example lists that were themselves acting as a bottleneck. Verified before/after with the same script: unique-question share rose from **~16% (808 of 5,179) to ~48% (2,523 of 5,179)** across the three banks, with the worst individual repeat counts cut from 150–189× down to about 20–30×. The bank is measurably more original than it was, though it is not the case that every one of the 5,000 slots is now a unique question — see "Known gaps" below for what full uniqueness would require and why it wasn't attempted in this pass.

## Seventh pass: flashcard split rebalanced to match real exam proportions

The user asked what the "normal" question split should be instead of an even 33/33/34 across SAT/ACT/TSIA2. Researched the actual current question counts on each real exam: Digital SAT is 98 total items (54 Reading & Writing + 44 Math); the current "Enhanced ACT" format (rolled out 2025) is 131 core items (English 50 + Math 45 + Reading 36, not counting the optional Science section); TSIA2's initial, non-adaptive screening is 50 items (20 Math + 30 ELAR). Scaling that real ratio (98 : 131 : 50) down to a 100-card deck rounds to 35 : 47 : 18 — ACT genuinely has the most questions of the three real exams, so it now has the largest flashcard share, and TSIA2's short initial screening gives it the smallest. Added 14 new ACT cards (semicolons, intro-phrase commas, nonessential "which" clauses, vague pronouns, dashes, less/fewer, matrices, absolute value, successive discounts, cylinder volume, claim-then-evidence structure, correlation vs. causation, multi-variable data, tone from word choice) and 1 new SAT card, and trimmed TSIA2 to 18 by keeping one card per official TSIA2 math domain plus its 11 strongest ELAR cards. Worth noting: this same real-exam-proportion data was already being used elsewhere on the site — the "Full Adaptive/Core Simulation" exam engines already use the official 27/27/22/22 (SAT) and 50/45/36 (ACT) per-module counts, so this flashcard rebalance now matches rather than contradicts the rest of the site.

## Eighth pass: TSIA2 Math/English targets, and a real live-update bug fixed along the way

The user asked for a TSIA2 target next to the existing SAT/ACT targets in the "Score goal" card, split into English and Math — unlike SAT (400-1600) or ACT (1-36), TSIA2 doesn't have one composite score; it's college-readiness pass/fail per domain. Researched the real current numbers: TSIA2 Math and ELAR are both scored on a 910-990 scale, with statewide college-ready benchmarks of Math >=950 and ELAR >=945 (plus an essay score >=5), set uniformly by Texas Administrative Code §4.57 — no Texas college can require a different readiness cutoff. Added two new inputs defaulting to those real benchmarks, saved alongside the SAT/ACT targets.

Deliberately did not fabricate a predicted TSIA2 scaled score the way SAT/ACT already get one — the app has an existing, honest design decision (see `renderTsiEstimate`) that TSIA2's adaptive scoring can't be concorded to a fake precise number, only a readiness label. The new goal-card line follows the same rule: recent practice accuracy plus the existing readiness label, next to the saved targets, never an invented 910-990 estimate.

Testing this surfaced a real, pre-existing bug worth fixing while in the same code: the goal card only ever rendered once, 300ms after page load, and never refreshed after a test actually finished in the same session — so completing a full SAT, ACT, or TSIA2 practice set wouldn't update the visible goal summary without a manual page reload. Added a live refresh call at the end of both test-finishing functions so all three now update immediately. Verified with Playwright: defaults render correctly, a changed TSIA2 target survives a reload, and a completed 16-question TSIA2 diagnostic updates the goal summary live in the same session — zero errors, full regression suite still clean.

## Turning on the contact form (Web3Forms)

`contact.html` ships with a real, working contact form — it just isn't connected to an inbox yet, on purpose, so no fake submissions ever silently vanish and no fabricated address is ever shown.

1. Go to [web3forms.com](https://web3forms.com) and enter the email address you want messages delivered to. No account or password is needed — you just verify that inbox once.
2. Web3Forms emails you a public **access key** instantly.
3. Open `contact.html`, find the hidden input `<input type="hidden" name="access_key" value="YOUR_WEB3FORMS_ACCESS_KEY">`, and replace `YOUR_WEB3FORMS_ACCESS_KEY` with the key you were emailed.
4. That's it — submissions now arrive in your inbox as an email. The access key is safe to leave visible in the page source: it can only be used to *send* a form submission to your verified address, never to read your inbox or send arbitrary email, and it is not your email address itself.
5. Optional hardening once you have a real domain: in the Web3Forms dashboard you can restrict the key to only accept submissions from `scorepathpractice.com`, and add a reCAPTCHA/Turnstile key for extra spam protection (the built-in honeypot field already blocks basic bots).

Until step 3 is done, visitors who submit the form see an honest "This form is not connected yet" message instead of a fake success confirmation.

## Monetization roadmap

Everything below is a concrete, honest next step — no invented traffic numbers, no guaranteed revenue figures (nobody can promise those for a site with no live traffic history yet), just what actually moves the needle for an ad-supported education site, in priority order.

1. **Get AdSense and Search Console live first — nothing else matters until traffic exists.** Ad revenue is a function of (pageviews) × (ad units seen) × (click-through rate) × (CPC), and right now the first factor is zero because the site isn't live. Steps 1–4 of "Turning on ads" and "Setting up Google Search Console" above are the actual first priority.
2. ~~**Build the 22 `skills/*.html` pages for real.**~~ Done in the Twentieth pass — see that section below.
3. **Fix the ~650KB single-file `index.html` load.** Every visitor downloads and executes the entire SAT + ACT + TSIA2 + Teacher engine on every visit, even a mobile visitor who only wants a 3-question TSIA2 diagnostic. Slow mobile load hurts both organic ranking (Core Web Vitals is a ranking factor) and ad viewability (a visitor who bounces before the page finishes loading never sees an ad). See item 1 under "Recommended next steps" above for why this is a real refactor project, not a quick fix.
4. **Consider a second monetization stream once there's real traffic to justify it** — for example a legitimate, disclosed affiliate program for SAT/ACT prep books (Amazon Associates or similar) linked from `resources.html`, or an optional donation/support link. Don't add either speculatively before there's traffic to make it worthwhile, and any affiliate relationship needs a real account and a real FTC-compliant disclosure — never a fabricated "as an Amazon Associate" line without an actual account behind it.
5. **Revisit ad density only after real AdSense data exists.** Right now there's exactly one ad slot per page — a conservative, policy-safe starting point. Once the account has real traffic and Ad Manager reporting, Google's own guidance (and simple A/B testing via AdSense's built-in experiments) is a better guide than guessing at a "more ads = more revenue" assumption up front, which frequently backfires via higher bounce rates.

## Going live checklist

- Every page uses `https://scorepathpractice.com` as its canonical/OG domain already (the homepage canonicalizes to the bare root, every other page to its own URL) — point your real DNS at this domain, or do a project-wide replace if you're using a different one.
- Paste a real Web3Forms access key into `contact.html` (see "Turning on the contact form" above) so messages actually reach you.

- Uncomment and fill in the real `google-site-verification` meta tag in `index.html` once you've added the property in Search Console (or use the HTML-file verification method instead — either works).
- Add a `CNAME` file at the repo root if hosting on GitHub Pages with a custom domain. `_redirects`/`vercel.json`/`.htaccess` are already included for Netlify/Vercel/Apache to 301 `/index.html` to `/`; GitHub Pages and Firebase Hosting serve `/` correctly by default with no extra file needed.
- **Repoint the site-wide "Teachers" nav links to `teacher-resources.html` before real launch.** Right now every "Teachers" link (header, footer, mobile quick-nav) goes straight to the live `teachers.html` tool — the right call while the site has no real visitors yet, since it's the fastest path for testing. Once the site is live on a real domain with real (unfamiliar) traffic, switch those links to `teacher-resources.html` instead: a nav link is mostly clicked by first-time visitors who don't know the product yet, a marketing page in front of the tool converts better and reads more professional than landing cold on an empty dashboard (0 Joined, 0 Working…), and `teacher-resources.html` currently has zero internal links pointing to it — only a `sitemap.xml` entry — which is a weak signal for Google versus a page that's actually linked from site navigation. This is a simple find-and-replace of `href="teachers.html"` → `href="teacher-resources.html"` in the relevant nav markup across all pages (and the matching CSS selector in `index.html`) when that time comes.
