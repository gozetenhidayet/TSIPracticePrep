# TSI Practice Prep

Free, original SAT / ACT / TSIA2 practice: skill-tagged questions with full explanations, mistake-pattern analysis (concept gap, process error, reading trap, pacing/guess), pacing tools, a Teacher Classroom for live in-class sessions with roster and error analytics, and an optional student account for cross-device sync.

V20 focused on clearer navigation, a simplified header, direct exam selection, a redesigned Teacher Classroom, and 6-character alphanumeric class codes.

## What this pass fixed and added

This repository came in as a "GitHub ready" export with a few gaps that would have broken it on a real static host. This pass closed those and layered on the pieces needed to run the site professionally, monetize it, and get it indexed:

**Fixed a real bug that broke most of the site.** `index.html` had two `$("heroTimed").onclick=...` calls targeting an element ID that doesn't exist anywhere in the page. Because that line lived inside a large inline `<script>` block, the resulting `TypeError` aborted the rest of that script — silently skipping the `satStore`/`satState`/`actStore`/`actState` declarations and everything after them. That, in turn, is why the SAT/ACT dashboards, mistake history, goal ring, and focus-lock features threw `is not defined` errors at runtime. Fixed with a small null-safe `safeClick()` helper; verified with Playwright that all pages now load with zero console errors.

**Fixed a second, separately-hidden bug in Teacher Classroom.** `teachers.html` read and wrote a `securityEvents` array (for the Secure Timed Mode activity log) that was never declared anywhere. Every call to `renderAll()` — including the one that runs immediately on page load — threw `securityEvents is not defined` partway through `renderRoster()`, which silently skipped `renderOverview()`, `renderQuestions()`, `renderStudentsTab()`, and `renderSkills()` every single time. In practice this meant the Overview, Questions, Students, and Skills analytics tabs never populated, ever — the single biggest feature this platform has over a plain question-answering site was completely non-functional. Fixed by declaring `securityEvents=[]` alongside the other session state. Verified end-to-end with two real browser tabs (a teacher room + a student joining, answering, and finishing): roster sync, live progress, and all four analytics tabs now populate correctly.

**Made a defensive console wrapper (`spConsole`).** Some embedding/preview contexts run pages inside a sandboxed `<iframe>` with a restricted `console` shim that only implements a subset of the real console API. This page called `console.info(...)` in three places (bank-size diagnostics) and `console.error(...)` in one; in an environment where `console.info` isn't a function, that throws and can abort a script block the same way the `heroTimed` bug did. All four calls now go through `spConsole(method, ...)`, which checks the method exists before calling it and silently no-ops instead of throwing if it doesn't. Verified by simulating a restricted console (only `log`/`warn`/`error`, no `info`) in Playwright — zero errors.

**Added real Open Graph / Twitter Card images and an Apple touch icon.** `index.html`, `sat.html`, `act.html`, `tsia2.html`, and `teachers.html` had no `og:image` at all, so a link shared in Slack, iMessage, or Twitter/X would render as a bare title with no preview image, and "Add to Home Screen" on iOS (outside the PWA manifest flow) had no icon to use. Generated `og-image.png` (1200×630, on-brand) and wired up `og:image`, `og:url`, `og:site_name`, `twitter:image`, and `twitter:card=summary_large_image` on all five pages, plus `<link rel="apple-touch-icon">`.

**Replaced the placeholder `contact.html` mailto link with a real contact form that never exposes an email address.** The old page displayed `support@tsipracticeprep.com` directly in the HTML (copyable and scrapeable) and did nothing but open the visitor's own mail client. No email address appears anywhere in `contact.html`'s HTML or JS. **Audited the entire 5,000-question bank and fixed a real generator bug that was silently duplicating questions.** *(Historical note added in the Twenty-eighth pass: at the time this section was written, the site's hero copy, about page, and Trust Center described the practice bank as having 5,000 original questions — that copy has since been changed to not state a specific number, see "Known gaps" and the Twenty-eighth pass below; the paragraph below is left as originally written to preserve the audit trail of what was found and fixed at the time.)* At the time of this pass, the site claimed (in its hero copy, about page, and Trust Center) that the practice bank had 5,000 original questions. To verify that claim, every question in `window.ScorePathBank` was extracted with Playwright and checked programmatically: structural completeness (unique ID, valid answer index, four unique choices, a real explanation, choice-by-choice rationale, a strategy tip — the same rule `QUESTION-BANK-QUALITY.md` already documents), full-text duplication (same question + passage + choices + answer as another item), and, for every math item whose format could be parsed, an independent recomputation of the correct answer from the numbers in the question text. The recomputation (1,122 math items checked) found **zero wrong answer keys** — every math item's marked answer really is correct. But the duplication check found a serious problem: the "5,000-question" generator (`v17SATOne`/`v17ACTOne`/`v17TSIOne`, the code that builds most of the bank) had a bug where a question's internal parameters were selected using `i % 12` (or `% 10` for TSIA2) — the exact same number used to pick *which* question template to use for a given slot. Whenever a parameter's own cycle length divided evenly into that same 12 (or 10), the parameter came out **constant** for every single item generated by that template, instead of varying. In practice this meant things like a circle's radius, a sentence's subject noun, or an example passage's name were frozen to one value for the entire life of a template — so the "5,000 questions" were actually well under 1,000 distinct questions, each copy-pasted under a different ID to hit the count target. The worst single offender ("Which inference is most reasonable?" in the TSIA2 bank) was the literal same question repeated 189 times. Fixed the root cause — parameters now derive from a separate counter (`Math.floor(i / cycle length)`) that is never tied to the template-selection index — corrected one knock-on math bug the fix exposed (a circle radius of 2 made two answer choices coincide), and meaningfully expanded several of the smallest hard-coded vocabulary/example lists that were themselves acting as a bottleneck. Verified before/after with the same script: unique-question share rose from **~16% (808 of 5,179) to ~48% (2,523 of 5,179)** across the three banks, with the worst individual repeat counts cut from 150–189× down to about 20–30×. The bank is measurably more original than it was, though it is not the case that every one of the 5,000 slots is now a unique question — see "Known gaps" below for what full uniqueness would require and why it wasn't attempted in this pass.

## Seventh pass: flashcard split rebalanced to match real exam proportions

The user asked what the "normal" question split should be instead of an even 33/33/34 across SAT/ACT/TSIA2. Researched the actual current question counts on each real exam: Digital SAT is 98 total items (54 Reading & Writing + 44 Math); the current "Enhanced ACT" format (rolled out 2025) is 131 core items (English 50 + Math 45 + Reading 36, not counting the optional Science section); TSIA2's initial, non-adaptive screening is 50 items (20 Math + 30 ELAR). Scaling that real ratio (98 : 131 : 50) down to a 100-card deck rounds to 35 : 47 : 18 — ACT genuinely has the most questions of the three real exams, so it now has the largest flashcard share, and TSIA2's short initial screening gives it the smallest. Added 14 new ACT cards (semicolons, intro-phrase commas, nonessential "which" clauses, vague pronouns, dashes, less/fewer, matrices, absolute value, successive discounts, cylinder volume, claim-then-evidence structure, correlation vs. causation, multi-variable data, tone from word choice) and 1 new SAT card, and trimmed TSIA2 to 18 by keeping one card per official TSIA2 math domain plus its 11 strongest ELAR cards. Worth noting: this same real-exam-proportion data was already being used elsewhere on the site — the "Full Adaptive/Core Simulation" exam engines already use the official 27/27/22/22 (SAT) and 50/45/36 (ACT) per-module counts, so this flashcard rebalance now matches rather than contradicts the rest of the site.

## Eighth pass: TSIA2 Math/English targets, and a real live-update bug fixed along the way

The user asked for a TSIA2 target next to the existing SAT/ACT targets in the "Score goal" card, split into English and Math — unlike SAT (400-1600) or ACT (1-36), TSIA2 doesn't have one composite score; it's college-readiness pass/fail per domain. Researched the real current numbers: TSIA2 Math and ELAR are both scored on a 910-990 scale, with statewide college-ready benchmarks of Math >=950 and ELAR >=945 (plus an essay score >=5), set uniformly by Texas Administrative Code §4.57 — no Texas college can require a different readiness cutoff. Added two new inputs defaulting to those real benchmarks, saved alongside the SAT/ACT targets.

Deliberately did not fabricate a predicted TSIA2 scaled score the way SAT/ACT already get one — the app has an existing, honest design decision (see `renderTsiEstimate`) that TSIA2's adaptive scoring can't be concorded to a fake precise number, only a readiness label. The new goal-card line follows the same rule: recent practice accuracy plus the existing readiness label, next to the saved targets, never an invented 910-990 estimate.

Testing this surfaced a real, pre-existing bug worth fixing while in the same code: the goal card only ever rendered once, 300ms after page load, and never refreshed after a test actually finished in the same session — so completing a full SAT, ACT, or TSIA2 practice set wouldn't update the visible goal summary without a manual page reload. Added a live refresh call at the end of both test-finishing functions so all three now update immediately. Verified with Playwright: defaults render correctly, a changed TSIA2 target survives a reload, and a completed 16-question TSIA2 diagnostic updates the goal summary live in the same session — zero errors, full regression suite still clean.

## Forty-sixth pass: fixed a real bug — the floating question-number navigator during a live test silently hid every question number past the first ten on any exam longer than 10 questions, i.e. every real SAT/ACT/TSIA2 practice test

Reported by the user with four screenshots of a TSIA2 Practice Test 1 session (questions 11, 12, 13, and the navigator pill) and the message "SORULAR ALTTA GOZUKMUYOR" (the questions don't show at the bottom). Confirmed as a real, previously-unreported CSS bug, not a one-off — it affected all three exams identically because they all share the same `.navigator`/`.navq` classes and the same `.practiceShell.show` focus-mode styling.

**Root cause:** `index.html` has three relevant rules. The base rule (`.navigator{display:grid;grid-template-columns:repeat(10,1fr)}`) lays the navigator out as a 10-column grid, so any test with more than 10 questions wraps onto additional rows. The focus-mode override (`.practiceShell.show .navigator{...}`) turns the navigator into a small floating pill with `max-height:53px;overflow-y:hidden` — but it never overrode `display`, so it silently inherited `display:grid` from the base rule. **Fix:** changed that same rule in `index.html` to `display:flex!important;flex-wrap:nowrap!important;align-items:center!important;` with `overflow-x:auto!important;overflow-y:hidden;white-space:nowrap`, and gave each `.navq` button `flex:0 0 auto!important`. The navigator is now a single horizontally-scrollable row instead of a silently-clipped grid — every question number is reachable, just by scrolling the strip instead of scrolling the page. Also added `document.querySelector('.navigator .current')?.scrollIntoView({inline:'center',block:'nearest'})` at the end of both `renderNav()` (the TSI-specific renderer) and `renderGeneric()` (the shared SAT/ACT renderer) in `question-bank-core.js`, so the strip auto-scrolls to keep the current question's button visible instead of leaving the student to hunt for it.

**Verified via Playwright** on all three exams, not just the one reported: on a live TSIA2 Practice Test 1 (44 questions), all 44 navigator buttons render, the computed style is `display:flex` with `overflow-x:auto` and a total height of 49px (confirming a genuine single row within the 53px pill), and clicking the previously-invisible button for question 40 correctly navigated to "Question 40 of 44." ## Fiftieth pass: measured, question by question, whether the bank's content actually resembles real SAT/ACT/TSIA2 questions — not just structure, actual passage lengths and question style — against freshly researched, sourced 2026 official specs

The user asked directly: do the questions really resemble real TSI, real SAT, and real ACT questions? This is a content-fidelity question, not a code bug hunt, so this pass first researched the current (2026) official specs for all three tests with sourced web search — importantly, **ACT changed its format nationally in April–September 2025** (English 50Q/35min, Math 45Q/50min, Reading 36Q/40min, all required; Science 40Q/40min is now optional and excluded from the composite; Math dropped from 5 answer choices to 4) — and then measured the actual bank content in `question-bank-core.js`/`practice-engine-core.js` against those real specs with small Python scripts (word counts, answer-choice counts, passage-reuse patterns), not just eyeballing a few examples.

**Good news, confirmed with hard numbers, on structure:** this site already reflects the *current* (2025+) ACT format, not the outdated pre-2025 one — `ACT_QUESTIONS` sections are English/Math/Reading/**"Science (Optional)"**, the blueprint weights used for full-length draws are exactly 50/45/36/40, and `FULL_SECTION_COUNTS.ACT=131` (50+45+36, correctly excluding the optional, non-composite Science section) — a scan of all 137 ACT Math items confirmed every single one uses 4 answer choices, not 5, matching the real 2025 change. SAT's Reading & Writing domain names (Information & Ideas, Craft & Structure, Standard English Conventions, Expression of Ideas) and Math domain names (Algebra, Advanced Math, Problem-Solving & Data Analysis, Geometry & Trigonometry) match College Board's real domain names exactly, and the one-short-passage-per-question format used for every SAT R&W item is itself the correct, real digital-SAT format (a common mistake would be legacy 500-word passages, which this site does not make).

**The real, newly-quantified content gap: passage length is consistently, substantially shorter than the real exams', on every passage-based section except SAT R&W:**
- **SAT Reading & Writing** (390 passages measured, all confirmed to actually have a passage attached): median 19 words, average 21–25, range 9–52. The real official range is 25–150 words — so **73% of this bank's R&W passages are shorter than the shortest real passage allowed**, and none come anywhere close to the 150-word upper end. The one-passage-one-question *format* is correct; the *length* skews too short.
- **TSIA2 ELAR** (140 items across 26 distinct passages, each correctly reused by ~5 questions — matching the real multi-question-per-passage pattern): median 30 words, average 32, range 9–64. The real official range is **100–400 words** — every single one of the 140 items falls short of the real minimum, by 3× to over 10×. This is the largest, most measurable gap found in this whole check.
- **ACT Reading** (122 items, but only **5 distinct passages** total, each reused ~24 times): average 40 words, range 32–58. Real ACT Reading passages run to several hundred words with roughly 10 questions each — so both the passage length and the passage diversity (5 unique passages for the entire ACT Reading bank) fall well short of a real Reading section's feel.
- **ACT English** (148 items): only 16 (the two passages `ACT_ENGP1`/`ACT_ENGP2`) are genuinely passage-embedded with real underlined-portion corrections — exactly the real ACT English format. The other 132 (89%) are standalone one-sentence grammar corrections with no passage at all, which is not how any real ACT English question is presented (every real item lives inside a full essay/passage). This specific ratio (16 of 148, ≈11%) sharpens what the Thirty-third pass had recorded as "17 of 95" — the fraction has gotten smaller as the English bank grew, not bigger.

**Where the content style genuinely does resemble the real thing:** TSIA2 Math's mix of short contextual "worked scenario" word problems (e.g., a triangle/rectangle/percent scenario in 1–2 sentences) alongside bare algebraic prompts (e.g., "If 7p − 4 = 8, what is p?") matches the real official TSIA2 sample questions' own domain-specific style split closely — Quantitative/Probabilistic Reasoning skewing contextual, Algebraic Reasoning skewing bare, exactly as College Board's own TSIA2 sample-question PDFs show. ACT Math's bare one-line equations are also a realistic match to plenty of real ACT Math items, which are frequently just as short.

**Already known and unchanged by this pass:** SAT Math still has **zero** Student-Produced-Response (grid-in/numeric-entry) questions — every Math item is multiple choice, while roughly a quarter of the real digital SAT's Math questions require typing in a number with no answer choices at all. This was already flagged as a fidelity gap in the Forty-first pass; this pass didn't newly discover it but confirms it's still fully true and, combined with the passage-length findings above, is one of the two biggest content-fidelity gaps in the whole bank (the other being TSIA2 ELAR's passage length).

**Not fixed in this pass, deliberately — this was a measurement pass, not a rewrite:** closing the passage-length gaps for SAT R&W, TSIA2 ELAR, and ACT Reading means hand-authoring substantially longer, still-original passages for hundreds of items (a real content-writing project, not a quick edit, and the kind of thing this README's "Known gaps" section already flags as dedicated-pass-sized work for related bank-quality issues); adding SAT grid-in questions means building a new answer-input UI (a free-response number field instead of the existing 4-choice button renderer) plus new content, which is a structural feature addition, not a content tweak. Both are now precisely quantified here so a future pass (or the site owner, if authoring the content directly) knows exactly how far off each section is and by how much, rather than a general "some passages could be more realistic" impression.

Added `assertTeacher(auth)` to `functions/lib/handlers.js`, which checks `auth.token.firebase.sign_in_provider !== 'anonymous'` (every real Firebase ID token carries this; students only ever get anonymous auth via `student-auth.js`, teachers only ever get real email/password auth via `teacher-auth.js`, so this needs no new schema) and rejects anonymous callers with `permission-denied`. `createRoom` now calls `assertTeacher` instead of the generic `assertAuthed`.
- **`getAssignmentQuestions` never checked that the room's exam matched the requested exam** — a caller could request TSIA2 questions against a room created for SAT (or vice versa), silently building a mismatched practice session. Now validates `room.examKey === data.examKey` and throws `failed-precondition` with a clear message if they differ.
- **The teacher-facing "Full section" question-count option silently capped at 24** instead of the real 98 (SAT) / 131 (ACT) / 44 (TSIA2) question count, because `parseCount()` in `functions/lib/pick.js` only recognized numeric labels like "20 questions," not the literal "Full section" option, and even after recognizing it, the unconditional `MAX_COUNT=40` clamp in `handlers.js` would have truncated it right back down. Fixed both: `parseCount` now special-cases "Full section" against a new `FULL_SECTION_COUNTS` constant (kept identical to the client-side constant already used in `student-room.html`), and the clamp now uses `Math.max(MAX_COUNT, FULL_SECTION_COUNTS[examKey])` so a legitimate Full Section request is never truncated while the free-text-adjacent numeric path stays capped at 40.
- **The Realtime Database rules for room events (`database.rules.json`) allowed unauthenticated read/write from anyone** (`.read: true, .write: true`, no auth check) on the classroom join/progress/security event stream. Changed to require `auth != null` for both read and write, with the root read/write left `false` (deny-by-default) so nothing outside `rooms/$roomCode/events` is reachable at all.
- **Classroom join codes (`teachers.html`'s `code()` function) were generated with plain `Math.random()`**, which is not cryptographically unpredictable. Changed to prefer `crypto.getRandomValues()` when available (every modern browser), falling back to `Math.random()` only if it genuinely isn't.
- Added three new test blocks to `functions/test/handlers.test.js` covering all of the above (anonymous callers rejected from `createRoom`; mismatched-examKey rejection with matching-examKey still working; "Full section" returning the real 98/131 instead of 24) — `cd functions && npm test` now runs 15 tests total, all passing, alongside the pre-existing 12.

**Fixed — a real, previously-undocumented SAT/TSIA2 adaptive-routing bug:** two live SAT adaptive controllers existed side by side — `satAdaptive` (the "Full Adaptive SAT" 98-question simulation) and `v9Adaptive` (the numbered "Practice Test" buttons) — implementing the identical Module 1 → Module 2 routing logic but at different accuracy thresholds (70% vs. 60%). A student could get routed into the harder Module 2 from one entry point but not the other at the exact same accuracy. Unified both behind one shared `SAT_ADAPTIVE_THRESHOLD=70` constant in `practice-engine-core.js`. While tracing this, found a second, related bug: `routeLabel()` (the function that displays "Higher-Difficulty Route" vs. "Foundational/Mixed Route" to students) always compared accuracy against a hardcoded 70, even for TSIA2's adaptive controller, whose actual routing decision used 60 — meaning a TSIA2 student scoring 60–69% was genuinely routed into the harder Module 2 while the on-screen label told them the opposite had happened. **Fixed — bank-wide answer-position imbalance (confirmed real):** the review's claim that correct answers cluster too heavily on certain letters checked out. ## Turning on the contact form (Web3Forms)

`contact.html` ships with a real, working contact form — it just isn't connected to an inbox yet, on purpose, so no fake submissions ever silently vanish and no fabricated address is ever shown.

1. Go to [web3forms.com](https://web3forms.com) and enter the email address you want messages delivered to. No account or password is needed — you just verify that inbox once.
2. Web3Forms emails you a public **access key** instantly.
3. Open `contact.html`, find the hidden input `<input type="hidden" name="access_key" value="YOUR_WEB3FORMS_ACCESS_KEY">`, and replace `YOUR_WEB3FORMS_ACCESS_KEY` with the key you were emailed.
4. That's it — submissions now arrive in your inbox as an email. The access key is safe to leave visible in the page source: it can only be used to *send* a form submission to your verified address, never to read your inbox or send arbitrary email, and it is not your email address itself.

Until step 3 is done, visitors who submit the form see an honest "This form is not connected yet" message instead of a fake success confirmation.

## Monetization roadmap

Everything below is a concrete, honest next step — no invented traffic numbers, no guaranteed revenue figures (nobody can promise those for a site with no live traffic history yet), just what actually moves the needle for a free, ad-supported (no subscription) education site, in priority order.

1. **Get AdSense and Search Console live first — nothing else matters until traffic exists.** Ad revenue is a function of (pageviews) × (ad units seen) × (click-through rate) × (CPC), and right now the first factor is zero because the site isn't live. Steps 1–4 of "Turning on ads" and "Setting up Google Search Console" above are the actual first priority. Once approved, the site now has **five** ad placements ready to receive real slot IDs — the homepage hub, the Trust section, the Teacher Tools page, the Thirty-ninth pass's new pre-test interstitial, and its new results-screen zone — all still honest empty placeholders until then.
2. ~~**Build the 22 `skills/*.html` pages for real.**~~ Done in the Twentieth pass — see that section below.
3. **Fix the ~650KB single-file `index.html` load.** Every visitor downloads and executes the entire SAT + ACT + TSIA2 + Teacher engine on every visit, even a mobile visitor who only wants a 3-question TSIA2 diagnostic. Slow mobile load hurts both organic ranking (Core Web Vitals is a ranking factor) and ad viewability (a visitor who bounces before the page finishes loading never sees an ad). See item 1 under "Recommended next steps" above for why this is a real refactor project, not a quick fix.
4. **Revisit ad density only after real AdSense data exists.** Right now there are five ad slots site-wide (up from three) plus the new pre-test interstitial, still a conservative, policy-safe starting point rather than an aggressive one. Once the account has real traffic and Ad Manager reporting, Google's own guidance (and simple A/B testing via AdSense's built-in experiments) is a better guide than guessing at a "more ads = more revenue" assumption up front, which frequently backfires via higher bounce rates — this is especially worth watching on a site aimed at students, where an overly aggressive ad experience risks the thing that brings visitors back in the first place.
5. **Other monetization channels worth considering, beyond display ads** — none built speculatively, since each needs a real account or a real decision from the site owner first:
   - **Affiliate/sponsor placements**, the same model as the Toolnova.tools card added in the Thirty-eighth pass: a small, clearly-labeled "sponsor" card or link, disclosed honestly, linking to a real partner. Natural candidates for a test-prep site: SAT/ACT/TSIA2 prep-book affiliate links (Amazon Associates or a publisher's own affiliate program) from `resources.html`, a graphing-calculator affiliate link (the TI-84 is already referenced in the Desmos-adjacent content), or a referral arrangement with a tutoring platform. Needs a real affiliate account and an honest FTC-compliant disclosure — never a fabricated "as an Amazon Associate" line without a real account behind it.
   - **An optional one-time donation/support link** (e.g., Ko-fi, Buy Me a Coffee, or GitHub Sponsors) — a lightweight way for the small share of visitors who want to support a free site to do so, with no account system or payment processing to build. Needs the site owner's own account; a fabricated donation link would be actively deceptive, not a placeholder, so this waits for a real one.
   - **Sponsored content on `teacher-resources.html`** once there's real teacher traffic — a tutoring company or prep-book publisher paying for a clearly labeled "Sponsored" placement is a normal, disclosed B2B revenue model for education sites, distinct from AdSense's programmatic ads.
   - **A future paid "Pro" tier**, if the site owner ever decides a subscription makes sense after all (extra question banks, printable teacher assignment packs, ad-free practice) — a real, separate project needing payment processing (e.g. Stripe) and account infrastructure, not something to bolt on lightly; flagged here only as an option, not a recommendation to build it now.
   - **School/district licensing** for the existing Teacher Classroom feature — once that flow has a real Firebase backend (see "Turning on cloud sync" above) and some organic teacher adoption, a paid per-classroom or per-school license is a plausible B2B path completely separate from the student-facing ad model.
